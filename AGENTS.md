# AGENTS.md: Link Vault

## 1. What this project is

Link Vault is a URL shortener with click analytics. The **frontend is already designed and must be preserved**. The job is to add a real **Node.js + Express + MongoDB (Mongoose)** backend and connect the existing frontend to it.

Core loop that must work end to end:

1. User pastes a URL and clicks Shorten.
2. Backend validates it, generates a unique short code, stores it in MongoDB.
3. Anyone opens `/<shortCode>`.
4. Backend checks the link exists and is not expired, atomically increments the click count, and redirects (302) to the original URL.
5. The click count is visible in the UI.

## 5. Data model (`Link`)

| Field | Type | Notes |
|---|---|---|
| `originalUrl` | String, required | Full destination, http/https only |
| `shortCode` | String, required, **unique index** | Generated by the server only |
| `ownerId` | String, required, indexed | Anonymous session id (see §7) |
| `createdAt` | Date | Use `timestamps: true`; stored in UTC |
| `expiresAt` | Date, optional | `null`/absent means never expires |
| `clickCount` | Number, default 0 | Total valid redirect requests |
| `lastClickedAt` | Date, optional | Updated on each counted click |

Do **not** use a MongoDB TTL index on `expiresAt`. Expired links must remain in the database so the server can respond "expired" and the UI can show status. Compare against the current time at request time.

## 6. API contract

All API responses are JSON. Errors use one consistent shape: `{ "error": { "code": "STRING", "message": "Human readable" } }`. Never return stack traces, Mongo error text, or credentials.

| Method & path | Purpose | Success | Errors |
|---|---|---|---|
| `POST /api/links` | Create link. Body: `{ originalUrl, expiresAt? }` | `201` with the link and `shortUrl` | `400` invalid URL/expiry, `429` rate limited |
| `GET /api/links` | List the current owner's links, newest first | `200` array | |
| `GET /api/links/:id` | Details for one link (owner only) | `200` | `400` bad id, `404` not found or not owner |
| `DELETE /api/links/:id` | Delete (owner only) | `204` | `400`, `404` |
| `GET /:shortCode` | Redirect | `302` to `originalUrl` | `404` unknown, `410` expired, `500` safe error page |

Every link object returned to the client includes: `id`, `originalUrl`, `shortCode`, `shortUrl` (built from `BASE_URL`), `createdAt`, `expiresAt`, `clickCount`, `lastClickedAt`, and a computed `status` of `"active"` or `"expired"`.

### Redirect route requirements

- Mounted **after** `/api` and static file handling, so it never swallows them.
- Match only valid code shapes (e.g. `/^[A-Za-z0-9]{6,10}$/`); anything else falls through to the 404 handler.
- Single atomic operation: `findOneAndUpdate({ shortCode, $or: [{ expiresAt: null }, { expiresAt: { $gt: now } }] }, { $inc: { clickCount: 1 }, $set: { lastClickedAt: now } })`. If it returns `null`, do one more lookup to decide between `404` (no such code) and `410` (expired).
- Respond with `302` and header `Cache-Control: no-store` so browsers do not cache the redirect and skip counting.
- Count `GET` requests only, not `HEAD`.
- On a database failure, return a safe error page. **Never redirect to an unverified destination.**
- 404 and 410 pages are small server-rendered HTML pages in the dark Link Vault style (black background, white text, red `#ee3a18` accent, Inter/system font), not JSON.

### What counts as a click

Each valid redirect `GET` request. This is an **approximate request count**. It does not filter bots or link-preview crawlers and does not measure unique people. Say so in the README. Do not claim otherwise anywhere in code, UI, or docs.

## 7. Ownership model (no authentication)

There are no user accounts. Links belong to an **anonymous browser session**:

- On first API request, issue an httpOnly, signed, `SameSite=Lax` cookie containing a random `ownerId` (use `crypto.randomUUID()`). Set `Secure` when `NODE_ENV=production`. Long expiry (e.g. 1 year).
- Every link is stored with that `ownerId`. `GET /api/links`, `GET /api/links/:id`, and `DELETE /api/links/:id` must filter by `ownerId`. A request for another owner's link returns `404`, not `403`.
- Describe this honestly in UI/docs as "links created in this browser". It is not a private account system and clearing cookies loses access to the list (the short links themselves keep working).

## 8. Validation and security (mandatory)

- Validate on the server regardless of frontend validation.
- URL: parse with `new URL()`, allow only `http:` and `https:`, require a hostname, maximum length 2048. Reject URLs whose host matches this app's own host (prevents redirect loops). Normalise by trimming. If there is no scheme, the server may prepend `https://` to match the existing frontend behaviour; document it.
- `expiresAt`: must parse to a valid date and be in the future. Reject past dates with `400`. Store as UTC.
- Short codes are generated server-side only (7 base62 characters from `crypto.randomBytes`/`crypto.randomInt`; no `Math.random`). Do not accept user-provided codes.
- Collisions: rely on the unique index, catch Mongo duplicate-key error `11000`, retry up to 5 times, then return a safe `500`.
- Reserved words that must never be issued as codes or conflict with routes: `api`, `assets`, `static`, `favicon`, `health`, `admin`.
- Use `helmet`, `express.json({ limit: '10kb' })`, and `express-rate-limit` on `POST /api/links` (e.g. 30 per 15 min per IP). Set `app.set('trust proxy', 1)` only when deployed behind a proxy and document this.
- Central error handler: log the error server-side (without secrets), return a generic JSON message to the client.
- Don't log full URLs with query strings at info level, or any visitor-identifying data. Do not collect IP addresses, user agents, or fingerprints.
- Convert `:id` params with a validity check (`mongoose.isValidObjectId`) before querying.

## 10. Serving the frontend

Express serves the `frontend` folder statically and serves `snip-connect.html` at `GET /`. Because the frontend and API share one origin, **CORS is not needed**. Do not add `cors` with a wildcard origin.

Route order in `server.js`:

1. Security and parsing middleware
2. Session (owner cookie) middleware
3. `/api/*` routes
4. Static files and `GET /`
5. `/:shortCode` redirect route
6. 404 handler, then central error handler

Connect to MongoDB **before** `app.listen`. Exit with a clear message if the connection fails.

## 11. Verification (required, not optional)

Before reporting done, actually run and observe these. Do not claim a result you did not see.

- Server starts and connects to MongoDB.
- Create a link: `201` with `shortUrl`.
- Visiting the short URL returns `302` with the correct `Location`, and `clickCount` increases by exactly 1.
